## 业务模块

> 本篇把四个业务模块的核心链路串起来：新闻浏览、用户认证、收藏、浏览历史。每个模块都按「接口 → CRUD → 数据」的顺序讲。

## 一、新闻模块

新闻模块有三个接口：分类、列表、详情。

**分类列表** `/api/news/categories`

直接查 `news_category` 表，走缓存。分类是低频变化数据，缓存 TTL 设为 7200 秒。

**新闻列表** `/api/news/list?categoryId=1&page=1&pageSize=10`

```python
offset = (page - 1) * page_size
news_list = await news_cache.get_news_list(db, category_id, offset, page_size)
total = await news.get_news_count(db, category_id)
has_more = (offset + len(news_list)) < total
```

列表走缓存（1800 秒），总量实时查库。返回 `{list, total, hasMore}`，前端根据 `hasMore` 决定是否继续上拉加载。

**新闻详情** `/api/news/detail?id=123`

详情接口做三件事：

1. 查新闻详情（缓存 300 秒）。
2. 浏览量 `views + 1`（更新数据库）。
3. 查同分类的相关推荐（缓存 1800 秒），按浏览量和发布时间排序。

```python
news_detail = await news_cache.get_news_detail(db, news_id)
views_res = await news.increase_news_views(db, news_detail.id)
related_news = await news_cache.get_related_news(db, news_detail.id, news_detail.category_id)
```

浏览量自增属于写操作，而详情缓存 TTL 是 300 秒，所以在缓存窗口内 `views` 会有一定延迟。

## 二、用户认证模块

用户模块有 5 个接口：注册、登录、获取信息、更新信息、改密。核心是「注册 → 登录 → Token 鉴权」这条链。

**注册** `/api/user/register`

```python
existing_user = await users.get_user_by_username(db, user_data.username)
if existing_user:
    raise HTTPException(400, "用户已存在")
user = await users.create_user(db, user_data)        # bcrypt 哈希密码
token = await users.create_token(db, user.id)         # 生成 UUID Token
return success_response("注册成功", UserAuthResponse(token=token, user_info=...))
```

密码用 passlib + bcrypt 哈希，不存明文：

```python
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
hashed = pwd_context.hash(password)
```

**登录** `/api/user/login`

```python
user = await users.authenticate_user(db, username, password)  # 查用户 + 验密码
if not user:
    raise HTTPException(401, "用户名或密码错误")
token = await users.create_token(db, user.id)
```

**Token 生成与校验**

Token 用 `uuid.uuid4()` 生成，存到 `user_token` 表，过期时间 7 天：

```python
token = str(uuid.uuid4())
expires_at = datetime.now() + timedelta(days=7)
```

同一用户已有 Token 则更新，没有则新建。校验时查 `user_token` 表，不存在或 `expires_at < now` 都返回 None。

**鉴权依赖** `get_current_user`

所有需要登录的接口都用这个依赖，完成「取 Authorization 头 → 去掉 Bearer 前缀 → 查 Token → 校验过期 → 返回用户」。

## 三、收藏模块

收藏有 5 个接口：检查状态、添加、取消、列表、清空。

**添加收藏** `/api/favorite/add`

```python
favorite = Favorite(user_id=user_id, news_id=news_id)
db.add(favorite)
await db.commit()
await db.refresh(favorite)
```

收藏表有唯一约束 `(user_id, news_id)`，数据库层面保证不会重复收藏。重复请求会触发唯一约束冲突，由全局异常处理器映射成提示。

**收藏列表** `/api/favorite/list`

联表查新闻内容和收藏信息：

```python
query = (
    select(News, Favorite.created_at.label("favorite_time"), Favorite.id.label("favorite_id"))
    .join(Favorite, Favorite.news_id == News.id)
    .where(Favorite.user_id == user_id)
    .order_by(Favorite.created_at.desc())
    .offset(offset).limit(page_size)
)
```

返回每行包含新闻对象、收藏时间、收藏 ID，路由层组装成 `{list, total, hasMore}`。

**取消收藏** `/api/favorite/remove?newsId=xxx`

按 `user_id + news_id` 删除，返回 `rowcount > 0` 判断是否成功。

## 四、浏览历史模块

历史有 4 个接口：添加、列表、删除单条、清空。

**添加历史** `/api/history/add`

逻辑是「有则更新时间，无则插入」：先查该用户对该新闻是否有历史记录，有就更新 `view_time`，没有就新建。

**历史列表** `/api/history/list`

和收藏列表类似，联表新闻按 `view_time` 倒序分页。

**删除单条** `/api/history/delete/{history_id}`

按 `history_id` 删除当前用户的记录。

**清空** `/api/history/clear`

删除当前用户所有历史记录。

## 五、四个模块的共性

| 共性 | 体现 |
| --- | --- |
| 统一响应 | 成功走 `success_response`，错误抛 `HTTPException` |
| 鉴权方式 | 收藏、历史、用户信息接口都用 `get_current_user` |
| 分页模式 | `offset = (page-1)*page_size` + `count` + `hasMore` |
| 缓存 | 新闻读接口走 Redis，用户/收藏/历史直接查库 |

## 六、小结

第四篇把四条业务链路走通：

- 新闻：分类/列表/详情 + 浏览量自增 + 相关推荐，列表和详情走缓存。
- 用户：bcrypt 密码哈希 + UUID Token（7 天有效）+ `get_current_user` 鉴权依赖。
- 收藏：唯一约束兜底、联表查询带收藏时间。
- 历史：有则更新无则插入，按浏览时间倒序。
