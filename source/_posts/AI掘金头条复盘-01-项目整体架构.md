## 项目整体架构

> 本系列以「AI掘金头条」为实战项目，把一个 FastAPI 后端从业务到部署完整复盘一遍。先从项目的业务边界、目录结构、技术选型和数据库关系开始。

## 一、项目是做什么的

「AI掘金头条」是一个前后端分离的新闻资讯类应用，核心能力有四块：

1. **新闻浏览**：分类、分页列表、详情、相关推荐。
2. **用户系统**：注册、登录、个人信息、改密。
3. **收藏与浏览历史**：用户对新闻的收藏、浏览记录管理。
4. **AI 问答**：前端直接调用 DashScope 的大模型，支持流式回答。

技术边界要先明确：**后端只提供业务数据接口，没有 AI 接口**。AI 问答由前端 `AIChat.vue` 直接请求模型服务完成，后端不参与这条链路。理解这一点，才能准确描述项目的能力范围。

## 二、项目结构

后端按「路由 / 数据 / 模型 / Schema / 配置 / 工具」拆分，入口 `main.py` 很薄：

```
backend/
├── main.py                  # 应用入口：注册路由、中间件、异常处理器
├── requirements.txt
├── routers/                 # 路由层：4 个业务模块
│   ├── news.py              # 新闻分类、列表、详情
│   ├── users.py             # 注册、登录、信息、改密
│   ├── favorite.py          # 收藏
│   └── history.py           # 浏览历史
├── crud/                    # 数据访问层
│   ├── news.py / news_cache.py
│   ├── users.py
│   ├── favorite.py
│   └── history.py
├── models/                  # ORM 模型
│   ├── news.py
│   ├── users.py
│   ├── favorite.py
│   └── history.py
├── schemas/                 # Pydantic 请求/响应模型
├── config/                  # 数据库与 Redis 配置
│   ├── db_conf.py
│   └── cache_conf.py
├── cache/                   # 新闻缓存封装
│   └── news_cache.py
└── utils/                   # 通用工具
    ├── auth.py              # Token 鉴权依赖
    ├── security.py          # 密码哈希
    ├── response.py          # 统一响应
    ├── exception.py         # 异常定义与处理器
    └── exception_handlers.py
```

入口文件 `main.py` 只做三件事：注册异常处理器、挂跨域中间件、挂载四个路由：

```python
app = FastAPI()
register_exception_handlers(app)

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

app.include_router(news.router)
app.include_router(users.router)
app.include_router(favorite.router)
app.include_router(history.router)
```

## 三、技术选型

| 层级     | 选型                            | 作用                |
| ------ | ----------------------------- | ----------------- |
| Web 框架 | FastAPI                       | 路由、参数校验、依赖注入、自动文档 |
| 数据校验   | Pydantic v2                   | 请求体校验、响应字段裁剪与别名   |
| ORM    | SQLAlchemy 2.0（async）         | 模型定义、查询、事务        |
| 数据库驱动  | aiomysql                      | 异步连接 MySQL        |
| 缓存     | redis.asyncio                 | 新闻分类、列表、详情、相关推荐   |
| 鉴权     | passlib + bcrypt + UUID Token | 密码哈希、登录态校验        |
| 前端     | Vue 3 + Pinia + Vant          | 页面与状态管理           |
| AI     | DashScope OpenAI 兼容接口         | 前端直连，SSE 流式问答     |

为什么这样选：FastAPI 原生支持 async 和 Pydantic，配合 SQLAlchemy 2.0 的异步引擎，整条链路从 HTTP 到数据库都能异步；Redis 用来扛新闻读请求的压力；Token 用 UUID 存数据库，适合学习鉴权链路。

## 四、数据库设计

仓库中可确认 6 个 ORM 模型，对应 6 张核心表：

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `user` | 用户 | id, username, password, avatar, bio, created_at, updated_at |
| `user_token` | 登录 Token | id, user_id, token, expires_at, created_at |
| `category` | 新闻分类 | id, name, sort_order |
| `news` | 新闻 | id, category_id, title, content, image, author, views, publish_time |
| `favorite` | 收藏 | id, user_id, news_id, created_at（user_id+news_id 唯一） |
| `history` | 浏览历史 | id, user_id, news_id, view_time |

关系上：`news.category_id → category.id`，`favorite/history.user_id → user.id`、`news_id → news.id`，`user_token.user_id → user.id`。

收藏表通过数据库唯一约束 `(user_id, news_id)` 保证「一个用户对一条新闻只能收藏一次」，即使业务代码没有先查重，数据库也会兜底。

## 五、启动流程

1. `uvicorn main:app` 启动，创建 `FastAPI()` 实例。
2. 注册全局异常处理器（HTTPException、数据库异常等）。
3. 挂 CORS 中间件。
4. 挂载 4 个业务路由，每个路由有自己的 `prefix` 和 `tags`。
5. 接收请求 → 参数校验 → 依赖注入（`get_db`、`get_current_user`）→ CRUD → 统一响应。

## 六、小结

本篇的目标是建立「全局视角」：

- 后端是 4 个业务模块（新闻、用户、收藏、历史），AI 不在后端。
- 代码按 Router → CRUD → Model/Schema 分层，配置和工具独立。
- 6 张表支撑全部业务，收藏用唯一约束兜底。
- 入口 `main.py` 只负责组装，业务逻辑分散在各路由。
