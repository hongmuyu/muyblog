## 域名注册（阿里云万网）

### 1. 选购域名

1. 访问阿里云万网：https://wanwang.aliyun.com/
![](/images/pasted-image-1793357348098.png)
2. 在搜索框中输入心仪的域名。建议使用 `.com`、`.cn` 或 `.me`，尽量简短好记。
![](/images/pasted-image-1793357362977.png)
3. 根据页面提示筛选后缀和价格，加入清单后，确定购买年限。个人博客建议直接购买 3-5 年，续费价格通常高于首年。
![](/images/pasted-image-1793357372619.png)点击购买并完成支付。

### 2. 实名认证（必做）

注意：国内注册的域名（尤其是 `.cn` 和 `.com`）必须进行实名认证，否则域名会被注册局暂停解析（ServerHold），导致网站无法访问。

1. 首次购买会提示进行实名认证。可以先完成支付，支付成功后，在阿里云控制台的“域名控制台”找到该域名，点击“未实名认证”提交资料（通常需要身份证正反面照片）。
2. 等待审核通过，通常需要 1-3 个工作日，有时几小时内即可完成。

关于备案：将博客托管在 GitHub Pages（境外服务器），不需要进行 ICP 备案，可以直接解析访问。

## 第二阶段：域名解析（DNS 配置）

域名购买完成后，需要将域名指向博客的托管服务器（GitHub Pages）。

### 1. 获取 GitHub Pages 的 IP 地址

GitHub Pages 的官方 IP 地址通常为以下四个：

- 185.199.108.153
- 185.199.109.153
- 185.199.110.153
- 185.199.111.153

### 2. 配置阿里云云解析

1. 进入阿里云域名控制台：[https://dc.console.aliyun.com/](https://dc.console.aliyun.com/)
2. 找到已购买的域名，点击右侧的“解析”。
3. 点击“添加记录”，添加以下两条核心记录：

| 记录类型 | 主机记录 (Host) | 记录值 (Value) | TTL | 作用说明 |
| --- | --- | --- | --- | --- |
| A | @ | 185.199.108.153（可添加多条 A 记录分别对应不同 IP） | 10 分钟 | 让主域名 `yourdomain.com` 指向 GitHub |
| CNAME | www | 你的 GitHub 用户名.github.io | 10 分钟 | 让 `www.yourdomain.com` 也能访问 |

![](/images/pasted-image-1793357387129.png)说明：如果 A 记录只能填一条，建议将四个 IP 分成四条 A 记录分别填写，主机记录均为 `@`。

## 第三阶段：博客项目端配置（Hexo）

此步骤为防止每次 GitHub Actions 自动部署后自定义域名失效的关键。

### 1. 修改 Hexo 主配置文件

打开博客源码根目录下的 `_config.yml`，修改 `url` 字段为你的域名：

```plain
url: https://yourdomain.com

```

![](/images/pasted-image-1793357294276.png)

2\. 添加 CNAME 文件

在 Hexo 的 `source` 目录下（注意是 `source` 根目录，不是 `_posts` 文件夹内），新建一个名为 `CNAME` 的文件（无后缀名），文件内容只写一级域名，不要带 `http://` 或 `www`：

```plain
yourdomain.com

```

原理：Hexo 构建时会将此文件复制到生成的静态文件根目录，告知 GitHub Pages 使用该域名。
![](/images/pasted-image-1793357451437.png)3. 推送代码

提交代码到 `main` 分支：

```plain
git add .
git commit -m "chore: add custom domain config"
git push origin main

```

## 第四阶段：GitHub 仓库设置

1. 打开博客源码所在的 GitHub 仓库。
2. 点击上方的“Settings”，在左侧菜单栏选择“Pages”。
3. 在“Custom domain”输入框中填入 `yourdomain.com`，点击“Save”。

![](/images/pasted-image-1793357465081.png)如果提示“DNS check unsuccessful”，通常是因为 DNS 尚未完全生效（TTL 延迟，通常等待 10 分钟至 24 小时不等），可稍后重试。

4. 等待 GitHub 检测到 DNS 成功后，勾选下方的“Enforce HTTPS”。GitHub 会自动申请免费的 SSL 证书，之后网站将通过安全的 HTTPS 访问。

## 常见问题排查

1. 域名无法访问：
    - 检查阿里云控制台域名状态是否正常（没有 ServerHold）。
    - 检查 DNS 是否生效：在终端运行 `ping yourdomain.com`，查看返回 IP 是否为 185.199.xxx.xxx。
2. GitHub Actions 部署后域名丢失：
    - 检查源码的 `source` 目录下是否存在 `CNAME` 文件，并确认其已提交至 `main` 分支。
3. 国内访问速度慢或不稳定：
    - GitHub Pages 的 IP 在国内偶尔不稳定。如果追求极致速度，可考虑将域名接入 Cloudflare 进行代理加速，或将博客迁移至国内的静态托管服务（需备案）。
