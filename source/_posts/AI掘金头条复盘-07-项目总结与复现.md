## 项目总结与复现

> 本篇是复盘的收尾：不看代码独立写一个接口、把整体架构讲清楚、回答常见技术问题、做自我总结。

## 一、闭卷复现：实现「新闻点赞」接口

检验自己是否真的掌握，可以独立实现一个项目里没有的接口。以「新闻点赞」为例，完整走一遍设计 → 编码 → 测试。

**1. 设计表**

```sql
CREATE TABLE news_like (
  id INT PRIMARY KEY AUTO_INCREMENT,
  user_id INT NOT NULL,
  news_id INT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY user_news_unique (user_id, news_id)
);
```

和收藏表类似，用唯一约束保证「一用户对一新闻只能点一次赞」。

**2. 定义模型**

```python
# models/news_like.py
from datetime import datetime
from sqlalchemy import Integer, DateTime, UniqueConstraint, ForeignKey
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

class Base(DeclarativeBase):
    pass

class NewsLike(Base):
    __tablename__ = "news_like"
    __table_args__ = (UniqueConstraint("user_id", "news_id", name="user_news_unique"),)

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    user_id: Mapped[int] = mapped_column(Integer, ForeignKey("user.id"), nullable=False)
    news_id: Mapped[int] = mapped_column(Integer, ForeignKey("news.id"), nullable=False)
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.now)
```

**3. 写 CRUD**

```python
# crud/news_like.py
from sqlalchemy import select, func, delete
from sqlalchemy.ext.asyncio import AsyncSession
from models.news_like import NewsLike

async def is_liked(db, user_id, news_id):
    result = await db.execute(select(NewsLike).where(NewsLike.user_id == user_id, NewsLike.news_id == news_id))
    return result.scalar_one_or_none() is not None

async def add_like(db, user_id, news_id):
    like = NewsLike(user_id=user_id, news_id=news_id)
    db.add(like)
    await db.commit()
    return like

async def remove_like(db, user_id, news_id):
    result = await db.execute(delete(NewsLike).where(NewsLike.user_id == user_id, NewsLike.news_id == news_id))
    await db.commit()
    return result.rowcount > 0

async def get_like_count(db, news_id):
    result = await db.execute(select(func.count()).where(NewsLike.news_id == news_id))
    return result.scalar_one()
```

**4. 写路由**

```python
# routers/news_like.py
from fastapi import APIRouter, Depends
from sqlalchemy.ext.asyncio import AsyncSession
from config.db_conf import get_db
from utils.auth import get_current_user
from utils.response import success_response
from crud import news_like

router = APIRouter(prefix="/api/like", tags=["like"])

@router.post("/toggle")
async def toggle_like(news_id: int, user=Depends(get_current_user), db: AsyncSession = Depends(get_db)):
    if await news_like.is_liked(db, user.id, news_id):
        await news_like.remove_like(db, user.id, news_id)
        liked = False
    else:
        await news_like.add_like(db, user.id, news_id)
        liked = True
    count = await news_like.get_like_count(db, news_id)
    return success_response("操作成功", {"liked": liked, "count": count})
```

**5. 挂载路由**

在 `main.py` 里 `app.include_router(news_like.router)`，重启服务即可用 curl 测试。

## 二、整体架构讲解

能闭卷讲清楚下面这条链路，就算掌握了：

```
浏览器
  │  HTTP / JSON
  ▼
FastAPI 路由（参数校验 + 依赖注入）
  │
  ├─ get_current_user → 查 user_token → 校验过期 → 注入 User
  │
  ├─ Redis 读缓存（分类/列表/详情/相关）
  │     ├─ 命中 → 直接返回
  │     └─ 未命中 → 查 MySQL → 写缓存
  │
  ├─ CRUD（select / update / delete）→ 事务 commit
  │
  ▼
Pydantic / jsonable_encoder
  │
  ▼
统一响应 {code, message, data}
  │
  ▼
浏览器
```

核心分层：Router 管 HTTP、CRUD 管数据、Model 管表结构、Schema 管进出格式、utils 管鉴权/响应/异常。

## 三、常见技术问题

**Q：为什么用异步？**
新闻读多写少，I/O 密集（数据库、Redis）。异步让单个请求在等 I/O 时让出事件循环，提高并发吞吐。

**Q：Token 为什么存数据库而不是 JWT？**
项目用 UUID Token 存 `user_token` 表，简单直观，方便学习鉴权链路。JWT 无状态、不需要查表，但吊销麻烦；数据库 Token 可以随时失效。

**Q：缓存和数据库不一致怎么办？**
以数据库为准，采用 Cache-Aside：写时删缓存、读时回填，TTL 兜底短时间不一致。

**Q：参数校验失败为什么返回 422 而不是统一格式？**
422 由 FastAPI 内置校验器处理，不经过项目的全局异常处理器。如果要统一，可以注册 `RequestValidationError` 处理器。

**Q：`expire_on_commit=False` 有什么用？**
默认 commit 后 ORM 对象属性过期，再次访问会触发隐式查询；异步环境下容易出错，所以关闭。

## 四、自我总结

这个项目的价值不在于「用了多少 FastAPI 语法」，而在于把一条完整的后端链路走通了：

```
HTTP → 参数校验 → 依赖注入 → 鉴权 → 业务编排 → 异步 ORM → 事务
     → 缓存 → 序列化 → 统一响应 → 异常兜底
```

比起记住多少 API，更重要的是知道：遇到新需求时，先设计表，再写 Schema，然后写 CRUD 和路由，最后补上鉴权、异常和测试。
