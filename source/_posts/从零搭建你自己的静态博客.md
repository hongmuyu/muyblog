很多人都想要一个自己的博客，但一想到要买服务器、装数据库、写后台管理，就被劝退了。

这个项目是一套**零服务器、零费用**的静态博客模板：Hexo 生成静态页面，GitHub Pages 托管，GitHub Actions 负责构建部署，再配一个网页后台，手机上也能写文章。

这篇文章教你如何把这个仓库变成你自己的博客。按顺序做完，大概能拥有一个和我一样的站点。

![](/images/pasted-image-1793428787964.png)一、这套模板能给你什么

- **访问快**：纯静态 HTML 托管在 CDN 上，没有数据库查询
- **不花钱**：GitHub Pages 免费，域名一年几十块（可选）
- **不会挂**：没有服务器可崩，流量再大也是 CDN 扛
- **随时能写**：浏览器打开 `/admin/`，手机、电脑都行，点发布就上线
- **数据是自己的**：文章和图片全部存在 Git 仓库里，历史版本永久可查

技术上它包含：Hexo + NexT 主题、GitHub Actions 自动部署、Sveltia CMS 网页后台、Giscus 评论、全站搜索、RSS、友链页。

## 二、准备工作

1. 一个 GitHub 账号
2. 电脑装好 **Node.js**（建议 LTS）和 **Git**
3. 可选：一个自己的域名（没有也能用默认的 `用户名.github.io`）

先检查环境：

```bash
node -v
git -v
```

## 三、拿到代码

有两种方式，按需选一个。

**方式 A：Fork**（想保留原仓库作为参照）

在 GitHub 上打开这个仓库，点右上角 **Fork**，创建一个属于自己的副本。

**方式 B：Clone**（想要一条干净的历史）

```bash
git clone https://github.com/hongmuyu/muyblog.git my-blog
cd my-blog
rm -rf .git
git init && git add -A && git commit -m "init: 基于 muyblog 模板"
npm ci
```

`npm ci` 会按 lock 文件安装依赖，第一次会稍慢。

然后在自己 GitHub 账号下新建一个**空仓库**，把本地推上去：

```bash
git remote add origin https://github.com/你的用户名/你的仓库.git
git branch -M main
git push -u origin main
```

四、改掉“我”的身份信息

这一步最关键。模板里到处写着我的站名、域名、仓库和联系方式，全部要换成你的。**漏改一处，上线后就会露馅。**

| 文件 | 需要改的字段 | 改成什么 |
| --- | --- | --- |
| `_config.yml` | `title`、`description`、`keywords`、`author` | 你的站名、签名、关键词、名字 |
| `_config.yml` | `url` | 你的域名，或 `https://用户名.github.io` |
| `_config.yml` | `github_pages.cname` | 同上 |
| `source/CNAME` | 全文 | 你的域名；**没有域名就删掉这个文件**（仓库根目录还有一个 `CNAME`，一并删） |
| `themes/next/_config.yml` | `social:` | 你的 GitHub、知乎、邮箱 |
| `themes/next/_config.yml` | `avatar.url` | 你的头像，替换 `source/images/avatar.png` |
| `source/about/index.md` | 全文 | 你的个人介绍 |
| `README.md` | 全文 | 你的博客介绍 |
| `source/_data/links.yml` | 首条 | 换成你自己的站或真实友链 |

改完之后，用一条命令自查还有没有漏网的：

```bash
grep -rn "hongmuyu\|zouwenxiang\|木与宁" \
  --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=public .
```

输出为空就说明干净了。

> `docs/` 和 `bin/` 里也有一些写死我域名和旧仓库名的脚本，如果你不打算用，直接删掉最省事。

## 五、清理示例内容

```bash
rm -rf source/_posts/*
rm -rf source/images/*
```

然后写你的第一篇文章（`hexo new post "文章标题"`，或者之后用网页后台写）。

**注意：`source/_posts` 里至少要保留一篇文章。** Hexo 在文章数为 0 时不会生成首页，整站会变成 404。模板的部署流程里加了检查，缺首页会拒绝发布，但最好别去踩这个坑。

## 六、接入网页后台（CMS）

模板已经内置了 Sveltia CMS，目录是 `source/admin/`，不用另外安装。你只需要把仓库地址改成自己的：

打开 `source/admin/config.yml`，修改这几行：

```yaml
backend:
  name: github
  repo: 你的用户名/你的仓库名
  branch: main

site_url: https://你的域名
display_url: https://你的域名
```

后台登录用的是 **GitHub 个人访问令牌（PAT）**，不需要任何服务器。

创建令牌：

1. GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. Repository access 选 **Only select repositories**，勾选你的博客仓库
3. Permissions 里把 **Contents** 设为 **Read and write**
4. 生成后复制令牌（以 `github_pat_` 开头，只显示一次）

![](/images/20261031-144248.png)

部署完成后，打开 `https://你的域名/admin/`，选 **“使用访问令牌登录”**，粘贴令牌即可。令牌保存在浏览器本地，下次不用再输。

## 七、配置评论（Giscus）

评论基于 GitHub Discussions，三步准备：

1. 仓库必须是 **public**
2. 在仓库 **Settings → General → Features** 里开启 **Discussions**
3. 安装 [giscus App](https://github.com/apps/giscus)，授权到这个仓库

然后去 [giscus.app](https://giscus.app/zh-CN)，填仓库名，类别选 `Announcements`，它会生成一段 `<script>`。

![](/images/pasted-image-1793429391311.png)**注意：`data-repo-id` 和 `data-category-id` 是仓库级别的 ID，不能照抄我的。** 把生成的那段脚本里这三行替换进 `source/_data/body-end.swig`：

```html
data-repo="你的用户名/你的仓库"
data-repo-id="你的 repo id"
data-category-id="你的 category id"
```

## 八、开启自动部署

进入仓库 **Settings → Pages**，把 **Source** 改成 **GitHub Actions**。

![](/images/pasted-image-1793429452138.png)模板里的 `.github/workflows/pages.yml` 会在每次 push 到 `main` 时自动构建并发布，不需要改任何东西。它还顺带做两件事：

- 构建产物缺少首页时**拒绝部署**，站点保持上一个正常版本
- 部署成功后自动把 `main` 同步到 `backup` 分支，多一份快照

![](/images/pasted-image-1793429607756.png)九、绑定自己的域名（可选）

1. 在 `source/CNAME` 写入你的域名
2. GitHub 仓库 **Settings → Pages → Custom domain** 填同样的域名并保存
3. 在域名服务商处添加解析：
    - 4 条 A 记录指向 `185.199.108.153`、`185.199.109.153`、`185.199.110.153`、`185.199.111.153`
    - 1 条 CNAME：主机记录 `www`，指向 `用户名.github.io`
4. 等证书签发后，在 Pages 设置里勾选 **Enforce HTTPS**

![](/images/pasted-image-1793429524022.png)绑 GitHub Pages 不需要 ICP 备案，域名实名认证完就能解析。解析生效一般几分钟，最慢 48 小时。

## 十、验收清单

推送后，依次确认：

- [ ] Actions 页面显示绿色（构建成功）
- [ ] 首页返回 200，标题和文章正确
- [ ] `/admin/` 能打开并登录
- [ ] 文章页底部能加载评论区
- [ ] `/atom.xml` 能访问（RSS 订阅）
- [ ] `/links/` 友链页正常

本地想先看效果：

```bash
npx hexo server
```

浏览器打开 `http://localhost:4000`。

## 十一、几个我踩过的坑

| 坑 | 说明 |
| --- | --- |
| 同时用 `hexo deploy` | 会和 Actions 互相覆盖，模板里已拆除，**别再装回来** |
| 删光所有文章 | Hexo 不生成首页，整站 404 |
| CNAME 没换成自己的 | 部署后自定义域名直接 404 |
| Decap CMS + GitHub 登录 | 静态站免服务器走不通，所以用的是 Sveltia + 令牌 |
| 页面一直转圈加载 | 多半是引用了被墙的 CDN，所有资源尽量本地化 |
| 发布后网页没更新 | GitHub Pages 有 CDN 缓存，等几分钟或强制刷新 |

## 十二、日常写作

配置完成后，你的写作流程就只剩三步：

1. 打开 `https://你的域名/admin/`
2. 写标题、选分类标签、敲正文、拖图上传
3. 点“发布”，等一分钟

后台的每次“发布”本质上都是一次 Git 提交，所以你在 GitHub 的提交历史里能看到所有操作，随时可以回滚。

建议把后台**添加到手机主屏幕**，它就像一个 App；电脑上可以用 Chrome 的“安装为应用”做成独立窗口。
