## 总结篇：FastAPI + MySQL 观看顺序与节点产出

### 一、总原则

- **FastAPI 为主线，MySQL 在对应节点插入**，不两门课从头并行硬看。
- 按编号顺序推进，不划分时间，自己控制节奏。
- 每个节点后标注**最低产出**，没有产出不算完成。
- **先跑通，再优化**：模型服务 HTTP 接口优先于索引优化。
- 存储过程、触发器、主从复制、分库分表暂时跳过。

---

### 二、优化版观看顺序 + 节点产出

1. **FastAPI P1–P4**：环境、快速入门、第一个接口
   **产出：** 能跑通第一个 FastAPI 服务，写出一个`GET /` 或`GET /hello` 接口。

2. **FastAPI P5–P7**：路径参数、查询参数、Path/Query 类型注解
   **产出：** 写出`/users/{id}`、`/users?skip=&limit=` 和带类型注解的查询参数接口。

3. **FastAPI P8–P9**：请求体、Field 类型注解、Pydantic 字段校验
   **产出：** 写出用户创建接口，Pydantic 校验必填、类型、长度、默认值。

4. **MySQL P1–P11**：数据库、表、字段类型基础
   **产出：** 能建库、建用户表和消息表，选对字段类型。

5. **MySQL P32–P33**：约束概述、主键、唯一约束
   **产出：** 用户表加主键和唯一约束（如邮箱唯一）。

6. **FastAPI P10–P14**：JSON/HTML/文件响应、自定义响应格式、异常响应处理
   **产出：** 接口有统一响应结构，能返回自定义异常格式。

7. **MySQL P34–P36**：外键约束、删除更新行为
   **产出：** 消息表带用户外键，理解删除/更新时的外键行为。

8. **FastAPI P15–P16**：中间件、`Depends` 依赖注入
   **产出：** 加一个请求日志中间件；用`Depends` 注入公共参数或数据库会话。

9. **MySQL P12–P20**：插入、更新、删除、条件查询、聚合、分组、排序、分页
   **产出：** 写出用户/消息的增删改查 SQL，包含条件、聚合、分组、排序、分页。

10. **FastAPI P17–P20**：ORM 简介、建表、在路由中使用 ORM、查询数据
    **产出：** 把用户表、消息表改成 ORM 模型，完成基础查询接口。

11. **MySQL P37–P41**：多表关系、内连接、外连接、自连接
    **产出：** 写出用户与消息的关联查询 SQL，理解内连接和外连接区别。

12. **FastAPI P21–P25**：条件查询、聚合查询、分页查询
    **产出：** 用户消息列表接口：按用户过滤、分页、统计消息数。

13. **FastAPI P26–P29**：ORM 新增、更新、删除、总结
    **产出：** 完成 ORM 增删改接口，能更新和删除用户/消息。

14. **MySQL P43–P47**：子查询
    **产出：** 写出标量、列、行、表子查询各一个例子，并能解释用途。

15. **MySQL P51–P55**：事务、提交、回滚、并发事务问题、隔离级别
    **产出：** 演示一次事务提交和一次异常回滚，理解隔离级别。

16. **FastAPI P30–P33**：项目简介、工程结构、模块化路由、数据库和 ORM 配置
    **产出：** 把项目拆成`routers/`、`models/`、`schemas/`、`db/`、`config`。

17. **FastAPI P30 之后的项目实战与接口测试章节**：严格按课程目录顺序看，写到哪个路由就测哪个路由
    **产出：** 每个核心路由至少 1 个正常测试 + 1 个校验失败测试 + 1 个异常测试，覆盖数据库读写。

18. **FastAPI 部署相关章节 + 模型服务 HTTP 接口封装**：项目跑通后再做
    **产出：** 封装`POST /predict` 或`/agent/run`，完成“请求体校验 → 调用模型 → 写执行记录 → 统一响应 → 异常处理 → 接口测试”。

19. **MySQL 进阶篇 P66、P72、P74、P80–P81、P84、P86**：索引概述、索引分类、索引语法、最左前缀法则、索引失效、覆盖索引与回表、单列与联合索引
    **产出：** 给用户表、消息表、任务表各设计一个常用索引，并写出验证 SQL。

20. **MySQL 进阶篇 P75–P78**：执行频次、慢查询日志、EXPLAIN
    **产出：** 用`EXPLAIN` 分析 3 条常用查询，判断是否走索引并写出优化前后 SQL。

21. **回看 FastAPI P20–P25**：把 ORM 条件查询、排序、分页和索引、EXPLAIN 对照理解
    **产出：** 能解释一条 ORM 条件查询/分页最终生成的 SQL 是否走索引。

22. **综合复盘**：按检查点过一遍，缺哪块回看对应分 P；复盘前给用户表、消息表、任务表各加一个常用索引，并用`EXPLAIN` 看一眼
    **产出：** 一份自己的“FastAPI + MySQL 速查笔记”，并能跑通一个带参数校验、数据库读写、错误处理、接口测试和模型 HTTP 接口的小项目。

---

### 三、关键配合点

- **FastAPI P8–P9 + MySQL P32–P36**：Pydantic 管接口入口校验，MySQL 约束管数据落库底线。
- **FastAPI P17–P29 + MySQL P12–P20**：ORM CRUD 和 SQL CRUD 对照学。
- **MySQL P37–P41 提前到 FastAPI P21–P25 之前**：先有 SQL 多表思维，再看 ORM 条件查询和分页。
- **FastAPI P26–P29 + MySQL P51–P55**：ORM 写操作和事务一起理解，重点做“创建任务 + 写执行记录”的异常回滚。
- **FastAPI P30–P33 回看 P14、P16、P17–P19**：项目拆分是把异常响应、依赖注入、ORM 配置重新组织。
- **MySQL 索引/EXPLAIN + 回看 FastAPI P20–P25**：ORM 条件查询、排序、分页最终要落到 SQL 和索引上。

---

### 四、最终检查点

1. 路径参数、查询参数、请求体分别放在哪里？什么时候用哪个？
2. Pydantic 能不能做字段类型、必填、长度、默认值校验？
3. 异常响应能不能统一格式？中间件和`Depends` 分别解决什么问题？
4. 能不能用 ORM 完成建表、查询、分页、增删改？
5. 多表连接和子查询能不能对应到 ORM 查询？
6. 一次请求写多张表，能不能开事务并在异常时回滚？
7. 项目能不能拆成模块化路由、配置、数据库会话？
8. 能不能给接口写测试：正常、校验失败、异常、数据库读写？
9. 模型服务能不能通过 HTTP 接口接收请求、返回统一响应、写执行记录？
10. 常用查询能不能用`EXPLAIN` 看是否走索引？

---

### 五、明确跳过

存储过程、触发器、主从复制、分库分表暂时不看。MySQL 进阶分 P 号如果对不上，按标题找：索引概述、索引语法、最左前缀、覆盖索引、联合索引、慢查询、EXPLAIN。

**一句话执行：** 按 1–22 顺序推进，每个节点完成标注产出再进入下一个；FastAPI 主线不断，MySQL 在节点插入；先打通接口和数据库 CRUD，再做事务、项目拆分、测试和模型 HTTP 接口，最后用索引和`EXPLAIN` 做优化。
