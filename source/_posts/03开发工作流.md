## 第一阶段：MVP验证（必须做）

不要直接开发全量系统。

先执行：

```text
读取：

FINAL_PRD.md

FINAL_TECH_SPEC.md

MVP_PLAN.md

任务：

实现 MVP。

验证：

1. 核心架构是否成立
2. 核心数据流是否成立
3. 关键风险是否可控

生成：

MVP_REPORT.md

如果 MVP 验证失败：

停止开发。

返回 TECH_SPEC 阶段。
```

---

## 第二阶段：生成开发工作流

建议新建：

```text
DEVELOPMENT_WORKFLOW.md
```

内容大概如下：
```
# AI Development Workflow

## 输入

FINAL_PRD.md

FINAL_TECH_SPEC.md

TASKS.md

---

## 开发原则

一次只允许开发一个任务。

禁止：

同时开发多个任务。

禁止：

一次生成整个项目。

---

## Task执行流程

选择：

TASKS.md

中优先级最高且依赖满足的未完成任务。

执行：

1. 实现代码
    
2. 编写单元测试
    
3. 更新README
    
4. 更新STRUCTURE
    
5. 更新TASK状态
    

完成后停止。

等待下一次任务。

---

## Code Review

每个Task完成后执行：

Architecture Review

Performance Review

Security Review

Maintainability Review

输出：

reviews/code_review.md

修复Critical问题后才能继续。

---

## Task状态

TODO

IN_PROGRESS

REVIEW

DONE

BLOCKED

---

## 集成检查

每完成一个Phase：

执行：

Integration Review

检查：

接口兼容性

数据库兼容性

缓存兼容性

事件流兼容性

---

## 停止条件

TASKS.md

全部DONE

进入Release阶段。
```
---

## 第三阶段：日常开发

以后你每天在 Claude Code 中只需要执行：

```text
读取：

FINAL_PRD.md

FINAL_TECH_SPEC.md

TASKS.md

DEVELOPMENT_WORKFLOW.md

选择下一个未完成任务。

完成：

1. 实现代码
2. 编写测试
3. 更新TASK状态
4. 更新README

完成后停止。
```

Claude 会：

```text
TASK-001
↓
开发
↓
测试
↓
Review
↓
DONE
```

而不是：

```text
把整个项目一次性写完
```

---

## 第四阶段：Release Readiness

当：

```text
TASKS.md

全部 DONE
```

执行：

```text
读取：

FINAL_PRD.md

FINAL_TECH_SPEC.md

全部代码

任务：

进行上线检查。

输出：

RELEASE_REPORT.md

检查：

功能完成率

测试覆盖率

性能压测

监控告警

部署文档

回滚方案
```
