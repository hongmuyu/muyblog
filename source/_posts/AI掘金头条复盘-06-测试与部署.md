## 测试与部署

> 本篇把项目跑起来并验证：接口怎么测、异常怎么测、环境怎么配、怎么容器化部署。

## 一、启动服务

后端：

```bash
cd backend
uvicorn main:app --host 127.0.0.1 --port 8080 --reload
```

前端：

```bash
cd frontend
npm install
npm run dev
```

启动后访问 `http://127.0.0.1:8080/docs` 可以打开 Swagger 文档。

![uvicorn 启动日志与 Swagger 文档页面](/images/ai-juejin-toutiao-uvicorn-swagger.png)

## 二、接口测试

项目里有一个 `test_main.http` 模板，可以用 curl 或 Swagger 逐个验证。

**新闻模块**

```bash
# 分类
curl "http://127.0.0.1:8080/api/news/categories"

# 列表
curl "http://127.0.0.1:8080/api/news/list?categoryId=1&page=1&pageSize=10"

# 详情
curl "http://127.0.0.1:8080/api/news/detail?id=1"
```

**用户模块**

```bash
# 注册
curl -X POST "http://127.0.0.1:8080/api/user/register" \
  -H "Content-Type: application/json" \
  -d '{"username":"test","password":"123456"}'

# 登录
curl -X POST "http://127.0.0.1:8080/api/user/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"test","password":"123456"}'

# 获取信息（需要 Token）
curl "http://127.0.0.1:8080/api/user/info" \
  -H "Authorization: 你的token"
```

**收藏 / 历史**（需要带 `Authorization` 头）

```bash
# 收藏列表
curl "http://127.0.0.1:8080/api/favorite/list?page=1&pageSize=10" \
  -H "Authorization: 你的token"

# 添加收藏
curl -X POST "http://127.0.0.1:8080/api/favorite/add" \
  -H "Authorization: 你的token" \
  -H "Content-Type: application/json" \
  -d '{"newsId":1}'
```

测试时重点看：响应结构是否是 `{code, message, data}`、分页字段是否正确、鉴权接口不带 Token 时的行为。

![登录接口的成功响应：返回 token 与 userInfo](/images/ai-juejin-toutiao-login-response.png)

## 三、异常测试

项目注册了 4 类全局异常处理器，按「具体在前、抽象在后」的顺序注册：

| 异常 | 处理器 | 返回 |
| --- | --- | --- |
| `HTTPException` | 业务错误 | 400/401/404 等 + `{code, message, data}` |
| `IntegrityError` | 数据库约束错误 | 400 + 「用户名已存在」等提示 |
| `SQLAlchemyError` | 数据库错误 | 500 + 「数据库操作失败」 |
| `Exception` | 兜底 | 500 + 「服务器内部错误」 |

`DEBUG_MODE=True` 时，错误响应的 `data` 字段会带上 traceback 和请求路径，方便本地调试。部署到公网时建议关闭。

可以测的异常场景：

- 重复注册同一用户名 → 400「用户名已存在」。
- 错误密码登录 → 401「用户名或密码错误」。
- 不存在的新闻详情 → 404「新闻不存在」。
- 不带 Token 访问收藏列表 → 422（Header 必填，由 FastAPI 内置校验器处理）。

## 四、自动化测试（可选）

用 `pytest` + `pytest-asyncio` + `httpx` 的 `ASGITransport` 可以不启动服务直接测接口：

```python
import pytest
from httpx import AsyncClient, ASGITransport
from main import app

@pytest.mark.asyncio
async def test_login():
    transport = ASGITransport(app=app)
    async with AsyncClient(transport=transport, base_url="http://test") as ac:
        r = await ac.post("/api/user/login", json={"username": "test", "password": "123456"})
        assert r.status_code == 200
        assert r.json()["code"] == 200
```

也可以用 `dependency_overrides` 替换 `get_db`，实现不依赖真实数据库的单元测试。

## 五、环境配置

当前数据库、Redis 连接参数写在 `config/` 里。如果需要多环境部署，可以收进环境变量：

```python
# config/settings.py
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    database_url: str
    redis_host: str = "localhost"
    redis_port: int = 6379
    debug: bool = False

    model_config = {"env_file": ".env"}

settings = Settings()
```

生产部署时不要把密码和 Key 写进源码或 README，统一从 `.env` 或环境变量读取。

## 六、Docker 部署

后端 Dockerfile 示例：

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8080
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8080"]
```

docker-compose 可以把 MySQL、Redis、后端一起编排：

```yaml
services:
  mysql:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: xxx
      MYSQL_DATABASE: news_app
  redis:
    image: redis:7
  backend:
    build: ./backend
    ports:
      - "8080:8080"
    depends_on:
      - mysql
      - redis
```

注意容器里的服务不能用 `localhost` 连 MySQL/Redis，要用服务名（如 `mysql`、`redis`）。

## 七、小结

第六篇掌握的核心：

- 用 curl 或 Swagger 逐个验证接口，重点看响应结构和分页。
- 4 类异常处理器覆盖业务错误、约束错误、数据库错误、未知异常。
- 可用 pytest + httpx ASGITransport 做自动化测试。
- 多环境部署用环境变量管理配置，不要硬编码密码。
- Docker + docker-compose 一键编排 MySQL、Redis、后端。
